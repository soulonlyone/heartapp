# 服务端部署指南

面向**第一次部署**的人。按顺序做完就能让客户端连上。

---

## 0. 先选模式

| 你的情况 | 选哪种 | 客户端填 |
|---|---|---|
| 只在家里/局域网用 | [明文局域网](#41-明文局域网快速测试) | `IP:8765` |
| 有域名，想要加密 | [nginx 反代](#43-nginx-反代推荐公网方案) | `wss://域名` |
| 没域名，但想加密 | [公网 IP 证书](#42-公网-ip-证书自动-tls) | `wss://IP` |

> 三种模式共用同一份程序，**切换模式不用重装**，改配置重启即可。

## 1. 前置条件

| 项 | 要求 |
|---|---|
| 系统 | Linux x86_64，**systemd**，glibc 2.28+（Debian 10 / Ubuntu 20.04 / RHEL 8 及以上） |
| 权限 | root（`sudo`） |
| 内存 | 128 MB 够用，建议 512 MB |
| 端口 | 见各模式说明，**云平台安全组必须放行** |

检查系统：

```sh
uname -m                        # x86_64
systemctl --version | head -1   # systemd 存在
ldd --version | head -1         # glibc ≥ 2.28
```

## 2. 下载安装包

去 [Releases](https://github.com/soulonlyone/heartapp/releases/latest) 下载：

```
HeartApp-Server-v1.5.0-linux.tar.gz    约 45 MB
```

它**自带 Python 3.12、websockets、Certbot**，服务器上不需要装 Python 或 pip。

```sh
cd /tmp
curl -fsSL --max-time 120 \
  "https://ghfast.top/https://github.com/soulonlyone/heartapp/releases/download/v1.5.0/HeartApp-Server-v1.5.0-linux.tar.gz" \
  -o srv.tgz
tar -xzf srv.tgz
cd heartapp-server-1.5.0
```

可选：核对校验和（和 Release 里的 `SHA256SUMS.txt` 对比）

```sh
sha256sum srv.tgz
```

## 3. 安装

### 3.1 交互安装（推荐）

```sh
sudo ./runtime/heartapp-server install --package-root .
```

会依次问：

```
HeartApp 服务端安装向导
这个密码用于客户端登录本服务器（不是房间密码），所有联机的人都要填同一个。
服务器访问密码（输入显示 *）：********
再输入一次确认：********
公网加密连接 IP（填了自动申请证书、监听 443；留空走本机或反向代理）：
服务端口 [8765]：
确认安装并启动服务？ [y/N]：y
```

- **公网 IP 那步**：想用自动证书就填公网 IP；想走 nginx 反代或局域网就**直接回车**
- **密码要求**：至少 8 位，不能是同一个字符重复，不能是 `12345678` / `password` 这类常见密码

### 3.2 非交互安装（脚本/自动化）

```sh
sudo HEARTAPP_INSTALL_PASSWORD='你的强密码' \
  ./runtime/heartapp-server install --package-root . \
  --host 0.0.0.0 --port 8765 --non-interactive
```

可用参数：

| 参数 | 说明 |
|---|---|
| `--password` | 访问密码（也可用环境变量 `HEARTAPP_INSTALL_PASSWORD`，更安全） |
| `--host` | 监听地址，默认 `127.0.0.1` |
| `--port` | 端口，默认 `8765` |
| `--public-ip` | 公网 IP，填了自动申请证书 |
| `--max-clients` | 总连接上限，默认 20 |
| `--room-size` | 每房人数，默认 4（最大 128） |
| `--user` | 运行用户，默认 `heartapp` |
| `--non-interactive` | 不提问 |
| `--no-open-port` | 不自动改防火墙 |
| `--dry-run` | 只打印将要做的事 |

`--dry-run` 会把要写的 systemd 单元完整打印出来，**不动系统**，适合先看一遍：

```sh
sudo ./runtime/heartapp-server install --package-root . --dry-run
```

### 3.3 一行安装

仓库里的 `deploy.sh` 会下载最新包并调用上面的安装：

```sh
curl -fsSL https://ghfast.top/https://raw.githubusercontent.com/soulonlyone/heartapp/main/server/deploy.sh | sudo bash
```

直连 GitHub 不通时它会自动换镜像；取不到校验和会中止（可用 `--no-verify` 跳过）。

## 4. 三种网络模式

### 4.1 明文局域网（快速测试）

```sh
sudo HEARTAPP_INSTALL_PASSWORD='强密码' \
  ./runtime/heartapp-server install --package-root . \
  --host 0.0.0.0 --port 8765 --non-interactive
```

- 监听 `0.0.0.0:8765`，自动放行本机防火墙
- **云安全组放行 TCP 8765**
- 客户端填 `服务器IP:8765`
- ⚠️ 密码和心率在网络上**明文可见**，只适合可信网络

### 4.2 公网 IP 证书（自动 TLS）

```sh
sudo ./runtime/heartapp-server install --package-root . --public-ip 你的公网IP --port 443
```

- 用内置 Certbot 向 Let's Encrypt 申请 **IP 证书**
- **要求独占 TCP 80**（HTTP-01 验证）——80 被 nginx 等占用会直接报错
- 证书短有效期，**每 12 小时自动检查续期**，续期时同样需要 80
- 云安全组放行 **TCP 80 和 443**
- 客户端填 `wss://你的公网IP`

### 4.3 nginx 反代（推荐公网方案）

服务只监听本机，证书由 nginx 管（复用已有域名证书）：

```sh
sudo ./runtime/heartapp-server install --package-root . --host 127.0.0.1
# 向导里公网 IP 留空
```

nginx 配置（加在 443 的 server 块里）：

```nginx
location / {
    proxy_pass http://127.0.0.1:8765;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_read_timeout 90s;
    proxy_send_timeout 90s;
    proxy_buffering off;
}
```

```sh
sudo nginx -t && sudo systemctl reload nginx
```

- 云安全组只需放行 **443**
- 客户端填 `wss://你的域名`
- **`Upgrade` / `Connection` 两个头必须写**，否则 WebSocket 握手失败，客户端一直卡在登录

## 5. 配置文件

所有配置在**一个文件**里：

```
/etc/heartapp-relay/config.json     权限 0640（root + 服务用户）
```

| 字段 | 默认 | 说明 |
|---|---|---|
| `host` | `127.0.0.1` | 监听地址；`0.0.0.0` 表示所有网卡 |
| `port` | `8765` | 服务端口 |
| `max_clients` | `20` | 总连接上限（1–10000） |
| `room_size` | `4` | 每房人数（1–128） |
| `user` | `heartapp` | 运行服务的系统用户 |
| `password` | — | 客户端登录服务器的访问密码 |
| `public_ip` | 空 | 填了启用自动 IP 证书 |

查看与修改：

```sh
sudo heartapp-server config show            # 密码显示为 ********
sudo heartapp-server config set port 9000
sudo systemctl restart heartapp-relay       # 改完重启生效
```

> 旧版部署（`.env` + `ExecStart` 两处配置）会在首次运行时自动迁移成 JSON。

## 6. 日常管理

```sh
sudo heartapp-server status        # 配置 + 服务状态 + 健康检查 + 客户端地址
sudo heartapp-server menu          # 交互菜单：状态/启停/日志/卸载
sudo heartapp-server health        # 只做健康检查

sudo systemctl status heartapp-relay --no-pager
sudo systemctl restart heartapp-relay
sudo journalctl -u heartapp-relay -n 50 --no-pager
```

证书相关（只有开启了自动证书才需要）：

```sh
sudo heartapp-server cert status
sudo heartapp-server cert renew
systemctl status heartapp-ip-renew.timer
```

### 升级

```sh
cd /tmp && rm -rf heartapp-server-* srv.tgz
curl -fsSL .../HeartApp-Server-v<新版本>-linux.tar.gz -o srv.tgz
tar -xzf srv.tgz && cd heartapp-server-<新版本>
sudo ./runtime/heartapp-server install --package-root .
```

- 安装是**幂等**的：配置、密码都保留
- 每次写入 `releases/<版本>/`，`current` 符号链接切过去
- **失败自动回滚**：恢复原单元、原配置、原版本指针和原服务运行状态
- 旧版本目录保留，便于排障

## 7. 卸载

```sh
sudo heartapp-server uninstall --dry-run      # 先看会删什么
sudo heartapp-server uninstall                # 执行
sudo heartapp-server uninstall --keep-config  # 保留配置（重装用）
sudo heartapp-server uninstall --remove-user  # 连系统用户一起删
```

会清掉：

| 内容 | 位置 |
|---|---|
| systemd 服务与续期定时器 | `heartapp-relay`、`heartapp-ip-renew.*` |
| 程序目录（含历史版本） | `/opt/heartapp-relay` |
| 命令入口 | `/usr/local/bin/heartapp-server` |
| 配置 | `/etc/heartapp-relay/config.json`（`--keep-config` 保留） |
| 证书与 ACME 数据 | `/etc/heartapp-tls`、`/etc/heartapp-acme` 等 |
| 防火墙规则 | 服务端口（`--no-open-port` 跳过） |

> 服务端**不保存任何心率历史**，没有数据需要备份。

## 8. 排障手册

| 现象 | 原因 | 处理 |
|---|---|---|
| `Changing to the requested working directory failed: Permission denied` | 版本目录权限错误（v1.4.4 的问题） | 升级到 v1.4.5+ |
| 健康检查 `Connection refused` | 服务没起来 | `journalctl -u heartapp-relay -n 50` 看原因 |
| 证书申请失败：`TCP 80 无法用于证书验证` | 80 被 nginx 等占用 | 改用 [nginx 反代](#43-nginx-反代推荐公网方案)，安装时公网 IP 留空 |
| 外网 `Test-NetConnection` 为 False | 云安全组没放行 | 控制台加入站规则 |
| 本机 `curl 127.0.0.1` 正常、外网不通 | 只监听了 `127.0.0.1` | `config set host 0.0.0.0` + 重启 + 放行端口 |
| 客户端一直「连接中」 | 反代缺少 `Upgrade` 头 | 按第 4.3 节补上 `proxy_set_header Upgrade/Connection` |
| 客户端提示密码错误 | 密码不一致 | `sudo heartapp-server config show` 确认，改完重启 |
| 频繁被断开 | 触发了「每 IP 每分钟 30 次」连接限制 | 等一分钟再试，或检查是否在反复重连 |
| `--public-ip` 报「需要公网 IP 地址」 | 填了内网地址 | 填公网 IP，或留空走反代 |

日志里不会出现房间码或心率数据——这是刻意的。

## 9. 安全建议

1. **别用弱密码**：一个密码保护整个服务器，所有联机的人共用
2. **公网务必加密**：明文模式下密码和心率可被中间节点看到，优先用 nginx 反代
3. **只开必要端口**：反代模式只开 443；明文模式只开 8765
4. **服务以专用低权限用户运行**：默认 `heartapp`，程序目录 root 所有
5. **服务端不存历史**：重启即清空，队友曲线只在内存保留 30 分钟
6. 房间里的人能看到彼此的心率——邀请朋友前先说明

## 10. 文件清单

| 路径 | 内容 |
|---|---|
| `/opt/heartapp-relay/current` | 当前版本（符号链接） |
| `/opt/heartapp-relay/releases/<版本>` | 历史版本目录 |
| `/etc/heartapp-relay/config.json` | 配置（含密码，0640） |
| `/etc/systemd/system/heartapp-relay.service` | 服务单元 |
| `/etc/heartapp-tls/current` | 证书（仅自动证书模式） |
| `/etc/heartapp-acme` | ACME 账户与申请数据 |
| `/usr/local/bin/heartapp-server` | 命令入口 |

## 11. 客户端怎么填

| 服务端模式 | 客户端「服务器地址」 |
|---|---|
| 明文 | `服务器IP:8765` |
| 自动 IP 证书（443） | `服务器IP` |
| nginx 反代（443） | `https://你的域名` 或 `wss://你的域名` |

不带 scheme 时：端口 443 走 `wss://`，其它端口走 `ws://`。

登录后创建房间，把 8 位房间码发给朋友即可。
