## 服务端：Linux 自包含包（新）

**目标服务器不需要安装 Python、pip 或任何依赖**——包里自带可移植 CPython 3.12、
websockets 和 Certbot，支持 x86_64、glibc 2.28+、systemd。

```sh
sha256sum -c SHA256SUMS.txt
tar -xzf HeartApp-Server-v1.4.3-linux-standalone.tar.gz
cd heartapp-server-1.4.3
sudo bash server/install-linux.sh
```

向导会依次询问：访问密码 → 公网 IP（可选）→ 端口 → 确认。

### 自动 IP 证书

填写公网 IP 后，安装器会：

1. 用内置 Certbot 通过 TCP 80 的 HTTP-01 验证，向 Let's Encrypt 申请**公网 IP 证书**
2. 默认监听 443，systemd 只授予 `CAP_NET_BIND_SERVICE` 权限
3. 每 12 小时检查一次续期，证书更新后重启服务
4. 证书身份不匹配或过期时客户端会拒绝连接

客户端直接填 `wss://公网IP`（默认 443）；自定义端口填 `wss://公网IP:端口`。

**前置条件**：云安全组放行 TCP 80 和 443；80 端口不能被其它网站占用。

### 安装可回滚

- 每次安装写入 `/opt/heartapp-relay/releases/<版本>`，`current` 符号链接指向当前版本
- 安装失败自动恢复原配置、原服务文件、原版本指针和服务运行状态
- 配置 `/etc/heartapp-relay.env`（600），私钥 `/etc/heartapp-tls`

### 统一管理入口

```sh
sudo heartapp-server              # 菜单
sudo heartapp-server health       # 带证书校验的健康检查
sudo systemctl status heartapp-ip-renew.timer
```

## 修复

- **校验和文件是 CRLF 时解析失败**（`awk` 比对不上），这是之前"没取到校验和"报错的真因；
  现在打包统一输出 LF，解析也兼容 CRLF
- **镜像前缀被拼接两次**（`ghfast.top/https://ghfast.top/...`），`--mirror` 实际不可用
- 下载过程显示每个源的尝试与失败原因，不再静默等待
- 缺少 `sha256sum`/`shasum` 时直接报错，不再跳过校验

## 已知限制

- **自动 IP 证书尚未在公网实测**：签发、跨天续期、Let's Encrypt 配额都需真机验证
- Debian 与 OpenCloudOS 上还需各复核一次
- 旧式源码包仍保留，但推荐用自包含包
- 心率为每秒 1 次广播，不是逐拍；HRV 只能当参考
- 未做各游戏反作弊兼容认证
