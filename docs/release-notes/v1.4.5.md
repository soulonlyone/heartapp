> **修复 v1.4.4 的安装失败：systemd 启动时 `Changing to the requested working directory failed: Permission denied`。**

---

## 这个版本修了什么

v1.4.4 把安装逻辑收进包内 CLI，但**版本目录权限建错了**：

```
Nov 23 13:51:12 heartapp-relay.service: Changing to the requested working directory failed: Permission denied
Nov 23 13:51:12 heartapp-relay.service: Main process exited, code=exited, status=200/CHDIR
```

原因：版本目录用 `tempfile.mkdtemp()` 创建，默认权限是 **0700**，安装时没放开，
于是服务用户 `heartapp` 无法进入 `WorkingDirectory=/opt/heartapp-relay/current`
（符号链接指向那个 0700 目录）。

修复：`/opt/heartapp-relay`、`releases/`、每个版本目录统一 **0755**，
并在 POSIX 上显式 `chown root:root`。新增一条回归测试检查这三层权限。

> 附带修复：回滚时若续期定时器不存在，不再输出 `Failed to disable unit` 的噪音。

## 安装（Linux）

```sh
cd /tmp && rm -rf heartapp-server-* srv.tgz
curl -fsSL --max-time 120 "https://ghfast.top/https://github.com/soulonlyone/heartapp/releases/download/v1.4.5/HeartApp-Server-v1.4.5-linux.tar.gz" -o srv.tgz
tar -xzf srv.tgz && cd heartapp-server-1.4.5
sudo ./runtime/heartapp-server install --package-root .
```

向导：访问密码 → 公网 IP（可选；80 被占用就留空走反向代理）→ 端口 → 确认。

非交互（明文，直接 IP 连）：

```sh
sudo HEARTAPP_INSTALL_PASSWORD='强密码' \
  ./runtime/heartapp-server install --package-root . \
  --host 0.0.0.0 --port 8765 --non-interactive
```

## 卸载

```sh
sudo ./runtime/heartapp-server uninstall --dry-run   # 先看清单
sudo ./runtime/heartapp-server uninstall             # 执行
sudo ./runtime/heartapp-server uninstall --keep-config  # 保留配置
```

## 装完验证

```sh
sudo heartapp-server status
curl http://127.0.0.1:8765/healthz     # OK
```

## 已知限制

- 自动 IP 证书需要独占 TCP 80；机器上有 nginx 等情况请用反向代理模式
- 证书每 12 小时检查续期，续期时同样需要 80
- Docker 容器与公网 WSS 压测仍未验收
