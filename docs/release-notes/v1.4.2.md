## 这版主要解决：杀毒软件误报

上一版有用户反馈解压后双击 exe，Windows Defender 直接提示
**「无法成功完成操作，因为文件包含病毒或潜在的垃圾软件」**并删除文件。

原因不是文件被投毒，是打包方式的固有特征：

- PyInstaller 的引导器（自解压结构）和加壳程序长得像，命中 `PUA:Win32/Packunwan`
- 我们的 exe **版本资源是空的**（没有公司名、产品名、版本号），在启发式眼里等于匿名文件

这版做了两件事：

1. **补全版本资源**：`CompanyName` / `ProductName` / `FileVersion` / `LegalCopyright`
   全部写入 exe，右键「属性 → 详细信息」能看到
2. **显式 `--noupx`**：不压缩，减少一层可疑特征

> 自签名证书的信任问题仍然存在（微软声誉系统不认），彻底解决需要付费代码签名证书。
> 如果仍被拦截，见下面「文件被误删怎么办」。

### 文件被误删怎么办

```powershell
# 1. 核对哈希（与 Releases 页 SHA256SUMS.txt 对比）
Get-FileHash .\HeartApp-v1.4.2-win64-portable.zip -Algorithm SHA256

# 2. 加排除项（推荐，只影响这个文件夹）
#    安全中心 → 病毒和威胁防护 → 管理设置 → 排除项 → 添加文件夹

# 3. 或从保护历史还原
#    安全中心 → 病毒和威胁防护 → 保护历史记录 → 找到记录 → 操作 → 还原
```

还担心的话可以直接跑源码（`python -m heartapp`），逻辑完全一样。

## 服务端：包含 v1.4.1 之后的全部修复

v1.4.1 发布后又在真机上修了几处，这版打包全部带上：

- **星号回显写到 stderr**：之前向导第一步就报 `操作未完成：not writable`
- **pip 调用全部限时**：升级 pip 卡住会无限期挂起，现在 20 秒超时 + 清华源回退 + 失败不致命
- **校验和不再依赖镜像站**：镜像拿不到 `SHA256SUMS.txt` 时改用仓库里的
  `server/checksums/v<版本>.txt`，两边都没有才中止
- **权限时序**：先 `chown root` 再执行安装目录里的程序，每次安装重建 venv

## 安装命令

```sh
u=https://raw.githubusercontent.com/soulonlyone/heartapp/main/server/deploy.sh; s=; for p in '' 'https://ghfast.top/' 'https://gh-proxy.com/' 'https://ghproxy.net/'; do s=$(curl -fsSL --connect-timeout 8 --max-time 25 "${p}${u}" 2>/dev/null) && break; done; [ -n "$s" ] && echo "$s" | sudo bash || echo "所有下载源都失败" >&2
```

GitHub raw 直连不通时自动换镜像。国内长期使用建议配 Gitee 镜像，
命令缩短到一行：见 [服务端文档](../server/README.md)。

## 已知限制（未变）

- 广播心率每秒 1 次，不是逐拍；HRV 只能当参考
- 只支持标准 BLE 心率服务
- 自签名证书不被微软信任，SmartScreen 仍可能提示
- 公网 WSS + 反代压测未验证；Docker 容器未在本机构建验收
