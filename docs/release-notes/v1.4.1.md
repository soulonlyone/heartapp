## 最重要的一条：服务端默认只监听本机

之前安装脚本默认 `--host 0.0.0.0`，装完就直接对公网开放，而访问密码和所有人的心率
都是**明文**传输。现在：

- **默认只监听 `127.0.0.1`**，反代或本机使用时无需任何额外配置
- 监听其它地址但没配 TLS 时，**服务端直接拒绝启动**：

```
拒绝在 0.0.0.0 上以明文启动：访问密码和心率都会明文经过网络。
  仅局域网使用：加 --allow-plaintext；
  公网使用：先配置 HTTPS 反向代理，本机监听 127.0.0.1（见 server/README.md）。
```

- 局域网玩法显式加 `--allow-plaintext` 即可，安装时会在输出里明确提示这条链路是明文的

Docker 与 Windows 启动器原本就是局域网入口，已显式带上该参数，行为不变。

## 密码策略

- 最少 **8 位**
- 拒绝全同字符（`aaaaaaaa`）和常见弱密码（`password`、`12345678` 等）
- 输入时显示 `*`，能看出输了几位；支持退格、中文按字符计数
- 向导里说明清楚：**这是客户端登录服务器用的访问密码，不是房间密码**

## 一行安装更耐折腾

- 直连 `github.com` 超时后，**自动依次尝试** `ghfast.top`、`gh-proxy.com`、`ghproxy.net`
- `api.github.com` 不通时，从仓库的 `server/LATEST` 读取最新版本号
- **取不到 `SHA256SUMS.txt` 时默认中止**（不再静默跳过校验）；
  确认来源可信后可用 `--no-verify` 跳过

## 修复

- **Linux/Docker 压缩包里的 `.sh` 是 CRLF**，在 Linux 上执行报 `$'\r': command not found`。
  现已强制转 LF
- **安装目录权限时序**：现在先 `chown root` 再执行目录里的任何程序，
  并且每次安装都重建 venv——避免升级时用 root 执行上一个版本留下的、可能被篡改的 pip
- `/healthz` 只返回 `OK`，不再暴露版本与协议号

## 升级须知

- **存量部署不受影响**：配置文件里已有的 `HEARTAPP_RELAY_HOST=0.0.0.0` 会被保留，
  安装脚本会据此给 systemd 单元加上 `--allow-plaintext`（升级输出里会提示明文风险）
- 想改成公网 + TLS 的推荐姿势：重装并加 `--host 127.0.0.1`，前面挂 Nginx / Caddy 终止 TLS
- 客户端不需要改动，可以继续用 v1.4.0 的客户端连本版本服务端

## 已知限制（未变）

- 广播心率每秒 1 次，不是逐拍；HRV 只能当参考
- 只支持标准 BLE 心率服务
- 公网 WSS + 反向代理的超时与压测仍未验证；Docker 容器未在本机构建验收
- 未做各游戏的反作弊兼容认证（软件不注入、不读内存、不采集输入）
