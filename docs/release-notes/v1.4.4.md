## 服务端：一个命令入口，自带卸载

以前安装要跑一堆 bash、配置分散在 `.env` 和 systemd 单元两处、卸载只能手删目录。现在全部收敛：

```
heartapp-server install      安装 / 重新配置（--dry-run 可预演）
heartapp-server uninstall    卸载（--keep-config / --remove-user / --dry-run）
heartapp-server status       配置、服务状态、健康检查
heartapp-server config       查看/修改配置
heartapp-server cert         IP 证书 setup / renew / status
heartapp-server run          systemd 调用
heartapp-server menu         交互菜单
```

### 安装

```sh
cd heartapp-server-1.4.4
sudo ./runtime/heartapp-server install --package-root .
```

向导会问：访问密码 → 公网 IP（可选，填了自动申请证书）→ 端口 → 确认。

非交互：

```sh
sudo HEARTAPP_INSTALL_PASSWORD='强密码' \
  ./runtime/heartapp-server install --package-root . \
  --host 0.0.0.0 --port 8765 --non-interactive
```

### 卸载（新）

```sh
# 先看会删什么
sudo ./runtime/heartapp-server uninstall --dry-run

# 卸载：停服务、删单元、删 /opt、删配置、删证书、关防火墙端口
sudo ./runtime/heartapp-server uninstall

# 保留配置 / 连用户一起删
sudo ./runtime/heartapp-server uninstall --keep-config
sudo ./runtime/heartapp-server uninstall --remove-user
```

装完后也可以直接用 `/usr/local/bin/heartapp-server`。

### 配置只有一份

`/etc/heartapp-relay/config.json`（权限 0640，属主 root、属组服务用户）。
不再有 `.env` + `ExecStart` 两处不一致的问题；旧版配置会在首次运行时自动迁移。

### 安装失败自动回滚

版本目录 + `current` 符号链接；安装失败会恢复原来的单元、配置、版本指针和服务运行状态。

## 修复

- **预发布版会被装成旧版**：`deploy.sh` 原来优先查 `releases/latest`（跳过 prerelease），
  现在优先读仓库 `server/LATEST`
- **一键安装命令简化**：单条 `curl` + 镜像前缀，回退逻辑收进脚本
- **IP 证书失败信息更明确**：80 端口被占用时直接提示「改用反向代理模式」
- 服务端 Linux 只发一个包（`-linux.tar.gz`），源码包下线

## 已知限制

- 自动 IP 证书需要**独占 TCP 80**；机器上已有 nginx 等情况请用反向代理模式（安装时不填公网 IP）
- 证书续期每 12 小时检查一次，续期时同样需要 80
- 公网 WSS 压测、Docker 容器构建仍未在本机验收
- 未被信任的证书/自签名场景客户端会拒绝连接
