# 客户端与联机服务端合并说明

- 目标分支为 `main`。功能提交 `374b2b7` 基于 `177117b`（v1.3.1）。合并前先拉取两条分支并检查最新差异。
- 来源分支为 `codex/client-and-relay-updates`。本说明随分支提交，供 DSH 审阅和整合。

## 改动

| 范围 | 内容 |
|---|---|
| 客户端 | 主窗口默认 860 × 600。实时页加入上次设备快捷连接、断开和停止确认、保存后直达本次回看。回看悬停显示实际采样时间。 |
| 小窗 | 单人和联机共用缩放、透明度和穿透设置。支持图片背景、调色盘、曲线时长及粗细，并可保存和切换含位置的小窗预设。预设里的背景图片引用本地文件。 |
| 本地数据 | 普通 Windows 单文件 EXE 使用 `%LOCALAPPDATA%\HeartApp\heartrate.db`。源码和便携版使用就地 `data`。旧库迁移保留原文件。录制使用数据库进程锁，另修复扫描覆盖连接状态、停止采集超时导致退出卡住的问题。 |
| 联机 | 服务端下发每房容量，创建区和房间列表直接展示。默认 4 人，服务端可设置 1～128 人，实际容量受总连接上限约束。客户端支持 `IP:端口` 或 `域名:端口`，裸地址带非 443 端口按 `ws://` 连接。需要在其他端口使用 TLS 时写明 `wss://`。联机面板按登录和入房状态显示操作。 |
| 服务端 | Linux 安装向导通过终端隐藏输入密码，确认端口后安装。`sudo heartapp-server` 可管理服务、日志、密码、端口和每房容量。Windows 面板和 Docker Compose 也可设置容量。 |

## 兼容和验证

- 协议版本仍为 v2，新客户端可连旧服务器。旧客户端收到超过 4 人的快照会报错，开放大房间前请同时更新两端。多人小窗最多同时展示 4 人，主界面图例可滚动，能查看和切换其余队友。
- 本地曾通过 185 项单元测试及 Qt、联机和服务端面板冒烟测试。容量扩展实际验证到 8 人收齐读数且第 9 人被拒绝。随后分别验证了创建区容量、简写地址登录、联机面板状态和回车操作。整合后以当前分支的重新验收结果为准。
- 合并后重新打包 Windows 客户端和服务端。新版 Linux Release 压缩包需包含 `server/manage-linux.py`，`deploy.sh` 才会启动新向导。当前正式版仍为 v1.3.1。
- Linux 向导已验证脚本语法、分发包内容及模拟管理流程。真实 systemd 环境的首次安装、升级保留配置、改密码、改容量和公网 WSS 仍需验收。
- 发布前请检查 Linux 安装目录的所有权。现有安装器把 `/opt/heartapp-relay` 交给服务用户，新的 `sudo heartapp-server` 从该目录执行 Python。应确保管理脚本、解释器及其父目录由 root 控制，服务用户只有运行所需的读取和执行权限。
