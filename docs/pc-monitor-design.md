# HeartApp：PC 心率监控

## 目标

观察用户在游戏、工作或其他 PC 活动中的心率变化；以一次 PC 使用过程为会话，
用手动事件标记对齐当时的心率。只展示观察数据，不将心率升高解释为紧张、压力或兴奋。

## 第一版交互

1. 扫描并连接标准 BLE 心率设备；没有设备时使用明确标注的 PC 模拟数据。
2. 选择游戏 / 工作 / 其他，填写会话名称，开始记录。
3. 前 30 秒收集本次参考基线；建议保持平常状态。基线建立后固定。
4. 主界面或置顶小窗查看当前读数及相对基线变化。
5. 按 Ctrl+Alt+F8 添加快捷标记，或输入事件名称并点击标记。
6. 停止后在历史页查看会话、心率曲线、标记时间线；导出心率与事件两个 CSV。

## 数据定义

- 基线：会话起始 0–30 秒内有效心率中位数，至少 20 条，覆盖至少 25 秒，相邻有效读数
  间隔不超过 5 秒。0 bpm 和明确未贴合的读数不能建立基线。起始数据不足则显示不可用。
- 基线不是临床静息心率，也不是跨天个人常模，不给出情绪判断。
- 新会话采样和事件均使用会话开始后的单调时钟秒数；实际时间保留用于历史列表。
- 最新读数超过 5 秒未更新或数据源不再连接时显示无实时读数；曲线超过 5 秒的间隔断开。
- PC 会话期间禁止替换数据源；断开会保留会话，用户可以结束保存。更换设备需先结束会话。
- 模拟来源在会话和小窗中明确标识，旧版本会话保留原有来源。

## 界面

主界面：设备连接行 → 当前心率 / 本次统计与基线、事件列表 → 最近五分钟曲线 →
会话类型与名称、事件输入 → 开始/停止、置顶小窗、导出。

历史页：会话列表 → 类型与名称、均值/峰值 → 基线、事件列表 → 带标记的心率曲线。
运动区间和 HRV 从默认 Qt 页面移除，旧统计接口和 Tk 兼容界面保留。
置顶小窗为普通 Windows 工具窗口；独占全屏及不同游戏的兼容性需真机验证。

## 架构与兼容

BLE / 模拟源 → 后台采集引擎 → SQLite。Qt 通过事件队列刷新，统计模块不依赖 UI。
新增 pc_sessions 和 session_events 表，外键关联原 sessions，删除会话级联清理；
原有样本表和 CSV 列保持兼容。新增事件 CSV 与心率 CSV 使用相同相对秒时间轴。
升级以建表方式添加结构，不修改旧采样。原会话没有 PC 元数据时仍可读取。

Windows 快捷键使用 RegisterHotKey，不注入游戏、不读取进程内存、不收集按键内容。
注册冲突时显示不可用，用户可用按钮标记；退出释放注册。其他系统仍可使用按钮。
事件列表包含全部标记，曲线最多显示视口内最后 12 个标签，避免重叠。

## 验证与后续

自动验证覆盖基线边界、低质量起始数据、旧数据库升级、事件持久化与级联删除、
系统校时不改变采样相对秒、Windows 快捷键消息、过期读数、小窗和历史事件回放。

后续优先：真表长时间采集、断线与休眠恢复、退出保存失败的恢复流程、独立定时落库。
之后再考虑前台应用识别、跨会话比较、悬浮窗位置保存及全屏游戏体验。
完整 RR 保存和 HRV 保留为后续独立任务。
