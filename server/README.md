# HeartApp 私人心率房间 · 初版

独立、自部署的 WebSocket 转发服务，支持域名、IPv4、IPv6（IPv6 地址用方括号包裹）。
不需要中央账号或公共服务器；所有参与者必须连接同一台服务端。
服务端不导入 GUI、BLE 或数据库，只依赖 Python 3.9+ 和 websockets。

当前为协议 v2 的源码测试版。Python 本机转发与双客户端流程已验证；
Docker 构建运行、公网 WSS 和压力测试尚未完成，不将下述配置视为已验证的线上容量。
合并与升级检查见 [main 合并交接说明](../docs/merge-handoff.md)。

## 本机 / 局域网试用

在仓库根目录安装 `server/requirements.txt` 后运行：

```sh
python -m heartapp.relay --host 127.0.0.1 --port 8765
```

客户端在「实时」主页点击「联机房间」，服务器填写 `ws://127.0.0.1:8765`。
先填写昵称、服务器地址和访问密码，点击「登录服务器」。登录后，下方房间列表显示同服房间，
可以创建命名房间、选择列表加入，或输入房间码加入。退出房间仍保持服务器登录，可直接换房。
登录保持在本次软件运行内；退出软件后不保存密码或会话令牌，下次启动重新登录。
每个人主动勾选「共享我的实时心率」后开始共享；模拟演示数据会明确标记。
本机双开客户端时请使用不同数据库，例如：

```sh
python -m heartapp --db data/player1.db
python -m heartapp --db data/player2.db
```

局域网部署改为 `--host 0.0.0.0`，客户端填写房主的局域网 IP，例如
`ws://192.168.1.20:8765`，并允许该端口的防火墙入站。裸 IP 也能使用，不强制域名。
IPv6 部署可指定 `--host ::`，客户端形如 `ws://[IPv6地址]:8765`。

## Docker Compose

在 `server` 目录复制 `.env.example` 为 `.env`，按需修改，然后：

```sh
docker compose up -d --build
docker compose ps
docker compose logs --tail=20
```

默认只映射服务器本机的 8765 端口，最多 20 个连接，0.5 核 / 384MiB 上限，日志轮转。
Dockerfile 以普通用户运行，不挂载个人记录，也不需要数据库。初版为源码构建，尚未发布镜像仓库。
关闭：`docker compose down`。服务重启会清除临时房间，需要重新创建；本地历史不受影响。

## 公网部署

建议使用已有 Nginx / Caddy 配置有效的 TLS 证书，将 HTTPS / WSS 入口代理到
`127.0.0.1:8765`，Nginx location 示例见 `nginx.conf.example`。
客户端填写 `https://hr.example.com` 或 `wss://hr.example.com`，会自动转换成 WebSocket 地址。
客户端验证系统信任的 TLS 证书，不提供忽略证书错误选项。直接使用公网 IP 时也需要匹配该 IP
且受客户端信任的证书，或通过可信的私人组网连接；`ws://` 只适合本机 / 可信局域网测试。
服务端也支持 `--cert fullchain.pem --key privkey.pem` 直接启用 TLS。

可选设置环境变量 `HEARTAPP_RELAY_PASSWORD` 限制整台服务器的访问；客户端密码不落盘，
复制邀请不包含访问密码。服务器运营者可接触经过其转发的心率，请只连接信任的服务端。
房间码用于定位房间，不是独立房间密码。同服已登录用户均可浏览并加入未满的房间。

家庭宽带是否可用取决于公网可达性、路由与防火墙，域名不会自动解决 CGNAT；动态公网 IP
可以配合 DDNS。不同服务器的房间不互通，初版没有自动穿透或中继发现。

## 协议及资源边界

- 协议版本 2：登录服务器与创建 / 加入 / 退出房间分离。客户端与服务端需要一起更新；
  v1 不再兼容，不兼容时明确提示。
- 每房间最多 4 人；每客户端每秒发送当前心率，共享关闭时不发送心率数值。
- 断流 5 秒后数值为空，不把旧值当实时；模拟来源保留标识。
- 主动退房 / 退出服务器立即移除成员；无成员房间删除。网络断开时保留 30 秒重连席位，
  数值立即清空，凭仅在内存的随机会话令牌恢复原身份和房间。超时后清理席位 / 会话。
  最多自动重试 5 次；服务重启不恢复房间，也不会偷偷新建旧房间。
- 单条入站消息最多 2KiB，限制消息频率、总连接数和连接尝试；发送缓冲有上限，慢连接会关闭。
- 同一来源 IP 每分钟最多 30 次尝试。经反向代理时共用该限额，初版仅适合小规模私人部署。
- 服务端不保存心率历史，不输出房间码或心率日志；健康检查为 `GET /healthz`。
- 联机小窗独立于主窗口，支持拖动、位置记忆、与个人小窗共用透明度及鼠标穿透设置。
  加入房间时 Ctrl+Alt+H 控制联机小窗；多人小窗固定尺寸，显示最近 60 秒临时曲线。
- 不实现共享历史、语音、视频、房主踢人、端到端加密或多实例房间同步。

客户端主页可临时比较多人曲线，最多保留 30 分钟；退出房间清空，不写入本地历史。
服务端使用 `sample_seq` 和 `age_ms` 字段，客户端用于去重和接收时序近似对齐。
曲线包含设备及网络延迟，
不代表各设备原始采样的精确同步；个人记录 / 导出依然只包含本人的数据。
联机小窗固定宽 430 逻辑像素，每人显示同刻度的最近 60 秒曲线。

2C2G 共用 agent 的情况建议从 20 人上限开始；以上是配置上限，不是已验证的公网容量。

房间目录最多返回前 100 个房间，每 5 秒自动更新，也支持手动刷新；不包含成员心率。
空闲 / 重连会话均只存于内存，断开后最多保留 30 秒，总会话数最多为连接上限的两倍。
